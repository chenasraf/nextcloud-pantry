Checklists are the heart of Pantry: shared shopping and to-do lists that everyone in the house sees
update in real time. An item can carry a quantity, a price, a category, one or more stores, labels,
an image, and a repeat schedule.

<Aside type="note">
	The web interface and the [companion app](/docs/getting-started/pairing) work on the same
	lists in your Nextcloud. Anything you change in one shows up in the other.
</Aside>

![A checklist in the Pantry web app, with items grouped under category headers and carrying quantities, prices, stores, labels and a weekly repeat.](/docs/checklists.png)

Each list has settings for its name, description, icon, color and access, plus
[item defaults](#item-defaults) that decide what new items on it start with.

**All checklists** shows every checklist item across the house in one place. To reuse the same
items again and again, keep them on a [template](/docs/using/templates).

## Add and check off items

A composer adds an item to the list. Checking an item marks it done: it strikes through and drops
to the bottom, and can be un-checked to bring it back.

The composer carries a row of chips — **Category, Stores, Labels, Quantity, Price, Description,
Recurrence, Image, Barcode** — so you can set an item's details as you add it.

![The checklist composer with chips for category, stores, labels, quantity, price, description, recurrence, image and barcode.](/docs/checklists-composer.png)

<Tabs syncKey="platform">
	<TabItem label="Web">
		- The composer sits at the **top** of the list, in a card titled **Add item**. Type a name in
		  the **Item name** field, set any chips you want, and press **Enter** or **Add**.
		- Click a row's checkbox to mark it done or undone.
		- Clicking elsewhere on a row does whatever your **Default item click action** setting says —
		  out of the box, nothing.
		- On a touch screen, long-press a row to start selecting several at once.
		- Each row's menu holds view, edit, copy to list, move to list, archive and trash.
	</TabItem>
	<TabItem label="Mobile & desktop">
		- The composer is pinned to the **bottom**, labeled **Add to …** with the list's name (or
		  **Add an item …** on All lists). Type there and tap send to add an item.
		- Tap a row's checkbox to mark it done or undone.
		- Tapping elsewhere on a row opens the item by default, and long-pressing starts a
		  multi-select — both are configurable.
		- Swipe a row for quick actions — view, edit, move, copy, archive, delete.
	</TabItem>
</Tabs>

<Aside type="tip">
	Checked items never just vanish — they strike through and stay recoverable, so an accidental tap is
	always undoable.
</Aside>

What a tap or click on a row does is up to you, in **Settings**:

<Tabs syncKey="platform">
	<TabItem label="Web">
		- **Default item click action** — Mark as done, View, Edit or None. Default **None**.

		A long-press on a touch screen always begins a multi-select; there are no swipe actions.
	</TabItem>
	<TabItem label="Mobile & desktop">
		- **Default item tap action** — Mark as done, View, Edit or None. Default **View**.
		- **Default item long-press action** — the same, plus Multi-select. Default **Multi-select**.
		- **Swipe actions** — on by default; turn it off to reach the same quick actions from a per-row
		  menu button instead.

		The same screen also sets the checkbox side, list density and long-name truncation.
	</TabItem>

### Adding something the list already has

As you type a name, matching items already on the list appear under the composer as **Already on
this list**. Tap one to reuse it instead of creating a second row for the same thing — bringing a
checked item back rather than duplicating it.

![The composer with "Bre" typed in, and Bread suggested under Already on this list with its quantity, price, repeat, category and store.](/docs/checklists-reuse.png)

Two settings shape this:

- **Reuse existing items** — what happens when the name you add already exists: **Always ask** (the
  default — a prompt offering **Reuse existing** or **Add anyway**), **Always reuse**, or **Never
  reuse**.
- **Suggest archived items** — off by default; turn it on to search archived items for suggestions
  too. Reusing an archived item unarchives it.

### Smart input

Type the amount along with the name and Pantry splits it off: **2 L milk** adds _milk_ with the
quantity _2 L_. Items you have added before also suggest the category and amount picked for them
then, so a regular shop mostly fills itself in.

What gets read out of a typed item:

| You type            | Item  | Quantity  |
| :------------------ | :---- | :-------- |
| `2 L milk`          | milk  | 2 L       |
| `500g flour`        | flour | 500 g     |
| `Milk 2L`           | Milk  | 2 L       |
| `3x eggs`           | eggs  | 3         |
| `eggs x3`           | eggs  | 3         |
| `2 bottles of wine` | wine  | 2 bottles |
| `1/2 cup sugar`     | sugar | 1/2 cup   |
| `- [ ] 6 eggs`      | eggs  | 6         |

- The amount can come before or after the name, as a number with a unit, a plain number in front
  (`2 eggs`), or a count like `3x`, `x3` or `3×`. Fractions (`1/2`, `½`) work too.
- Units are matched in English and metric symbols everywhere, plus the words of the language Pantry
  is set to. Languages that write `1,5` use a decimal comma.
- A word after a unit like _of_ (`2 bottles of wine`) is dropped from the name.
- A number that is part of the name stays in it: `7up`, `3M tape` and `Pixel 8` are added as typed.
- Markdown list markers (`-`, `*`, `1.`, `[ ]`) are removed, so a pasted list adds cleanly.

**Suggestions learn from your household.** When you add an item by a name you have used before,
Pantry suggests the category the house usually picks for it, and on the same list, the amount you
added it with last time. A suggestion only fills a detail you have not set: the list's
[item defaults](#item-defaults), a scanned [barcode](#barcodes), and anything you pick yourself
always win. Names match loosely — case, accents and notes in brackets don't matter, so _Milk (2%)_
counts as _milk_.

Each guess shows as a chip you can drop before adding:

- Dropping an **amount read from what you typed** keeps the text in the name, for when the number
  really is part of it.
- Dropping a **suggested category or amount** tells Pantry the guess was wrong, so it is less likely
  to suggest it for that item again.

<Tabs syncKey="platform">
	<TabItem label="Web">

		turned on, each line gets its own row of chips, and so does each item in a Markdown

	</TabItem>
	<TabItem label="Mobile & desktop">
		Guesses fill the composer's **Category** and **Quantity** chips; tap the **×** on a chip to drop

</Tabs>

![The add item form with "500g rice" typed in, showing chips for the 500 g read from the text and a suggested Dry goods category.](/docs/checklists-smart-input.png)

![Multiple mode with four lines typed. Rice, jam and tomatoes each get a row of chips for their amount and category; "Pixel 8 case" is left as typed.](/docs/checklists-smart-input-multiple.png)

On [inventories](/docs/using/inventories), the amount remembered is the one typed when adding an
item — updating its stock count later does not change what is suggested.

Smart input is on by default. Turn it off from **Settings** → **Interface** → **Smart input** to
have every item added exactly as typed. On the web the choice is saved to your account, so it
applies in every browser; in the app it applies to that device.

## Item defaults

A list can pre-fill the composer, so that every item you add to your groceries list starts at your
usual store, or every item on a chores list starts as recurring. Open **Item defaults** from the
list's **⋯** menu, from the tune button at the end of the composer's chip row, or from **Edit item
defaults** in the list's settings.

The dialog shows the composer's chips for the details a list can pre-fill: **Recurrence, Stores,
Category, Labels, Quantity** and **Custom fields**. Open a chip and pick how it starts:

- **Not set** — new items start without a value, as on a list without defaults.
- **Fixed** — new items always start with the value you pick below.
- **Remember last** — new items start with whatever the last item added to this list used. The
  chip reads, for example, **Stores: last used**.

![The Item defaults dialog, with the Stores chip set to Fixed on Supermarket and Recurrence set to remember the last used value.](/docs/checklists-item-defaults.png)

Quantity can be **Fixed** but not remembered. Price, description, image and barcode always start
empty, since they belong to a single item.

Each custom field can likewise use its **Field default** (the default set on the field itself),
a **Fixed** value for this list, or **Remember last**.

A pre-filled chip is only a starting point: change it in the composer before adding, and only that
item is affected — unless the detail is set to **Remember last**, in which case the next item starts
with your change. In **All checklists**, the composer uses the defaults of the list you pick to add to.

<Aside type="note">
	Item defaults are shared by everyone in the house. Only people who can edit a list can change
	its defaults, but anyone who adds items to it updates what **Remember last** remembers.
</Aside>

## Item details

Set any of these from the composer chips as you add an item, or open an existing item to change them:

- **Quantity** — free text, so a unit comes along for the ride ("3", "400 g", "2 x 1 L"). The **+**
  and **−** buttons step the number inside it and leave the rest alone, in a 1-5-10 progression that
  grows with the value — 8 → 9 → 10 → 15, 400 → 450 → 500 — so a large quantity is a few taps away
  rather than a hundred.
- **Price** — an amount (or a range) used to estimate shopping totals.
- **Category** — one category, shown as a colored header that groups the list.
- **Stores** — one or more shops where the item is bought.
- **Labels** — free-form tags for filtering.
- **Image** — attach a photo so everyone recognizes the exact product. Upload one from your device,
  or pick one you already keep in your Nextcloud files and either link it in place or import a copy,
  as on the [Photo Board](/docs/using/photo-board#photos-from-your-nextcloud-files).
- **[Custom fields](/docs/using/custom-fields)** — your own fields (a text note, a number, a
  yes/no flag, a date, or a list of choices) that you define for the house or a single list.

![A checklist item showing its details inline — quantity, price, an attached image, a weekly repeat and its store.](/docs/checklists-item.png)

### Barcodes

Scan or enter a product **barcode** (EAN or UPC) to prefill a new item from it — Pantry looks up the
product and fills in its name, category and photo for you to review before adding. If no product
matches, fill in the item yourself.

You can **scan** with your camera on the phone app, and in the web interface when a camera is
available; on the desktop app, type the barcode in by hand.

## Organize with categories, stores and labels

Three independent ways to organize a list:

- **Categories** group items under colored headers (Bakery, Dairy, …). An item has at most one.
- **Stores** mark where each item is bought (Supermarket, Home Depot, …), and drive
  [Shopping Mode](/docs/using/shopping-mode) routes.
- **Labels** are free-form tags for anything else.

You create and manage each set from its picker — **Create category…**, **Create store…**,
**Create label…** — and can rename, recolor or delete them there.

Categories are shared by the whole house: a new one is offered on every checklist and every
[inventory](/docs/using/inventories), whichever list you create it from, so your shopping list and
your fridge sort things the same way. To keep a category to one list, pick that list under **List**
when you create or edit it.

Above the list, a free-text filter plus **Categories**, **Labels**, **Stores** and **Price** filters
narrow what you see.

![The filter row above a checklist — a text filter and dropdowns for categories, labels, stores and price.](/docs/checklists-filters.png)

### Estimated total

In the web interface, a checklist or template shows an **Estimated total** above its items: each
unchecked item's price times the number in its quantity, added up. It counts only the items the
filters and search leave on screen, so filtering to one category and searching a keyword shows what
just those items will cost. Price ranges give a range, each currency gets its own total, and with a
single store filtered, items use their price at that store.

## Recurrence

Every item is one of three kinds, set from the **Recurrence** chip:

- **Staple** — stays on the list after it is marked done.
- **One-time** — removed from the list once marked done.
- **Recurring** — comes back on a schedule.

A new item starts with whatever recurrence its list's [item defaults](#item-defaults) give it. A
new list remembers the recurrence of the last item added.

### Repeat schedules

A recurring item repeats on a schedule — for the groceries you buy every week. Presets cover
**Daily**, **Weekly**, **Every 2 weeks** and **Monthly**; past those, build the rule yourself from
**Every _n_** days, weeks, months or years:

- **Weeks** — the weekdays to repeat on.
- **Months** — either **days of the month** (leave it empty to repeat on the same day each month),
  or **a weekday of the month**: First, Second, Third, Fourth or Last, paired with a weekday — the
  second Tuesday, the last Friday.
- **Years** — a **date of the year** (leave it empty to repeat on the same date each year).

A repeat can also **end**: never, after a number of occurrences, or on a date. A summary of the rule
you built is shown as you go.

![The repeat editor in the composer: presets, an every-n-weeks rule repeating on Thursday, end options, the completion-interval toggle and a summary reading "every week on Thursday".](/docs/checklists-recurrence.png)

Pantry brings the item back on its **next recurrence** after it is checked off, anchored one of two
ways:

- **On a fixed schedule** (default) — the item comes back on its next scheduled date, no matter when
  you actually tick it off. A weekly item stays on the same weekday even if you shop a few days late.
- **Starts after completion** — turn this on to count the interval from when the item is ticked off
  instead. A "every week" item you buy two days late then returns a full week _from that purchase_,
  not from the original date.

## Import and export

You can move lists in and out of Pantry as Markdown checklists:

- **Import from Markdown** — paste a Markdown list or drop a `.md` file to create items in bulk.
- **Export to Markdown** — copy the list out as a Markdown checklist.

You can also **copy** or **move** items to another list from the item menu. The item keeps its
category, labels, custom fields and barcode. Any that belonged only to the old list are matched to
the new list's own, or copied over when it has none.

## Archive and trash

- **Archive** an item to take it off the active list without deleting it — archived items stay
  available to bring back later. Whole lists can be archived too.
- **Trash** an item or list to soft-delete it. Trashed things can be restored, or permanently
  deleted, from the trash view.

Once a shop or a chore is behind you, the **Done** section's menu clears it in one go:

- **Archive all** moves every checked item in the list to the archive.
- **Remove all** moves every checked item in the list to the trash.

Both cover the whole list rather than only what a filter or search currently shows. Each asks for
confirmation first, and the message that follows carries an **Undo**.

<Aside type="caution">
	Emptying the trash or permanently deleting cannot be undone. Everything else — checking off,
	archiving, trashing — is recoverable.
</Aside>
