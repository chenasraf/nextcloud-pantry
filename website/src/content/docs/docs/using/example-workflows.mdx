Pantry doesn't force one way of working — lists, items and [Shopping Mode](/docs/using/shopping-mode)
can be mixed however suits your house. The workflows below are common starting points. Each one
answers the same question: what happens to the list once you're done with it?

## The weekly grocery list

**One list you keep, not a new list every trip.** Lists are meant to be reused: items carry their
stores, price, category, labels and [custom fields](/docs/using/custom-fields), and all of that
would be lost if you started from scratch each week.

<Steps>

1. **Create one "Groceries" list** and add items to it whenever you notice you need something.

2. **Pick a [recurrence](/docs/using/checklists#recurrence) for each item.**
   - Milk you buy every week? Make it **Recurring**, repeating weekly on your shopping day.
   - Something you need once — a birthday cake, a replacement bulb? Make it **One-time**, so it
     leaves the list once you check it off.
   - Something always on hand that you restock whenever you run out? A **Staple** stays on the list
     after being checked, ready to un-check when it's needed again.

3. **Go shopping.** Open **Start shopping** from the list, pick the stores you'll visit, and check
   items off as they go into the cart.

4. **Finish the trip** and enter what you actually paid in the review, if you want to track
   spending. Past trips stay in your shopping history.

5. **Let the list reset itself.** Recurring items come back un-checked on their schedule, one-time
   items are gone, and the list is ready for next week — no duplicating, archiving or renaming
   needed.

</Steps>

<Aside type="tip">
	Set the list's [item defaults](/docs/using/checklists#item-defaults) so new items start the way
	most of yours do — for example, **Recurring** every week at your usual store.
</Aside>

### Resetting by hand

If you'd rather not use schedules, the **Done** section's **⋯** menu works on every checked item in
the list at once:

- **Uncheck all** returns them all to the active list, ready for the next trip.
- **Archive all** puts them away, out of sight but available to bring back later.
- **Remove all** moves them to the trash.

## Errands and pickups

**A list whose items never come back.** Package pickups, returns, one-off errands — once done,
there's nothing to keep.

<Steps>

1. **Create a list** — for example "Mail pickups".

2. **Open its [item defaults](/docs/using/checklists#item-defaults)** and set **Recurrence** to
   **One-time**, so every new item leaves the list once it's checked off.

3. **Add each errand** with what you need to get it done — a tracking number and pickup point in
   the description, or in a [custom field](/docs/using/custom-fields).

</Steps>

The list empties itself as you go, and only shows what's still waiting.

## Shared household chores

**One list, mixed recurrence, the whole house working from it.** A general to-do list that anyone
in the house can pick up from.

- **Recurring** for regular chores — water the plants every few days, change the bedsheets every
  two weeks. Turn on **Starts after completion** for chores that should come back a set time after
  they were last done, rather than on fixed dates.
- **One-time** for things that only need doing once — fix the cabinet hinge, call the plumber.

Everyone sees the list update as items are checked off, so nobody does the same chore twice. See
[Sharing](/docs/using/sharing) for who can see and edit a list.

## A repeatable project checklist

**A template you start each run from.** Some checklists are the same every time but each run needs
its own record — a packing list for every trip, the steps for setting up each new project, the
checks for each move-out.

<Steps>

1. **Build a [template](/docs/using/templates)** once with every step, organized with categories
   and labels. A template is never checked off, so it stays a clean master copy.

2. **Start each run from it**, whichever way fits:
   - **Take everything.** Choose **Duplicate template** from the template's menu, name the copy
     after the trip or project it's for, and pick **Checklist** under **Duplicate as:**. The copy
     brings along every item, category and setting, all unchecked.
   - **Pick what applies.** Create the run's checklist, then **Apply template** and untick the steps
     that don't apply this time — no pet food on a trip without the dog.

   ![The Duplicate template dialog, with a name for the copy and Checklist picked under Duplicate as.](/docs/duplicate-list.png)

3. **Attach the template to the run.** With the template under **Templates:** in **Edit
   checklist**, any step you left out is suggested again as soon as you start typing it.

4. **Work through the run.** When you notice a step the template is missing, add it to the template
   too, so the next run has it.

5. **Archive the run** when it's over, so it's out of the way but still there to look back on.

</Steps>

<Aside type="note">
	Use this when each run needs its own history. For things you simply do again and again — like
	the weekly shop — one reused list with recurring items is simpler.
</Aside>

## Staples suggested everywhere

**Type a few letters, get the item with all its details.** The things you buy over and over —
bread, milk, eggs, dish soap — live once on a template, and every list suggests them as you type.

<Steps>

1. **Create a "Weekly staples" [template](/docs/using/templates)** and add each staple the way you
   want it to arrive: quantity, usual store, category, price.

2. **Open Edit template and turn on Every list** under **Suggest in:**, so every checklist and
   inventory in the house suggests its items — including lists made later.

3. **Add items as usual.** Typing "cro" on Groceries suggests **Croissants** with the template's
   name on a chip; picking it adds the item with its quantity, store and price already filled in.

4. **Before a big shop, apply the whole template.** **Apply template** on Groceries ticks every
   staple the list does not have open yet; untick what you still have and apply the rest in one go.

</Steps>

<Aside type="tip">
	Keep a few small templates rather than one big one — "Weekly staples", "Cleaning", "Baby" — and
	attach each only to the lists it belongs on, so suggestions stay relevant.
</Aside>

## A pantry that restocks itself

**Count what you have; let the shopping list follow.** Instead of remembering to add things to the
list, keep an [inventory](/docs/using/inventories) of the cupboard and let Pantry add whatever runs
low.

<Steps>

1. **Create a "Pantry" inventory** and add what you keep there. Give countable things a **Count**
   with a **Target** ("12 eggs") and, if you like a buffer, a **Reorder point**. Give flour, spices
   and oil a **Level** with a **Restock amount** ("1 kg bag").

2. **Pick a restock checklist.** In **Inventory settings**, set **Restock checklist** to your
   Groceries list.

3. **Step stock down as you use things.** Tap **−** when you open the last carton, or set a level to
   **Low**. Once an item is low, the inventory shows **Low · buy 8 eggs** and Eggs appears on
   Groceries asking for those 8 eggs.

4. **Shop as usual.** Checking the item off on Groceries, or in Shopping Mode, puts what you bought
   back into the Pantry inventory.

</Steps>

Nothing to reset: the inventory is back to full, and the Groceries item waits, checked off, until
stock runs low again.

<Aside type="tip">
	Keep a **Fridge** inventory next to the Pantry one with the same restock checklist. Items with the
	same name share one shopping-list row, which asks for what both need — and buying it fills them in
	turn.
</Aside>

## Food that expires

**Dates you don't have to check.** For the fridge and freezer, it is not running out that matters
but what is about to expire.

<Steps>

1. **Give perishables an expiry.** In the item's **Expiry** card, pick **Keeps N days** — 7 for
   milk, 21 for eggs. The date becomes today plus that many days, and every restock renews it.

2. **Set how much warning you want.** **Expiry warning** in **Inventory settings** decides how many
   days ahead an item turns amber. Two days suits most fridges.

3. **Turn on the Daily stock summary** in **Inventory settings**. Once a day, everyone who can see the
   inventory gets one notification with what newly ran low, ran out, started expiring or expired.
   Opening it shows just those items.

4. **Replace, don't add.** An expiring item asks the restock checklist for a full replacement, and
   buying it replaces the old stock with a fresh date.

</Steps>

<Aside type="note">
	Pantry never throws anything away for you: expired stock stays on hand until you step it down. Use
	**−** when you bin it.
</Aside>

## Stocking a new cupboard from a template

**Set up a place once, then fill it in seconds.** A holiday home, a new flat, the camping box — when
you know what a place should hold, write it down once and start every inventory from it.

<Steps>

1. **Build a template** of everything the place should hold, with a stock mode, target and how long
   each item keeps.

2. **Duplicate it as an inventory.** Choose **Duplicate template** and pick **Inventory** under
   **Duplicate as:**. Every item arrives full, with its expiry counted from today.

3. **Count down to reality.** Walk the cupboard and step down what is short; the low items land on
   the restock checklist, ready for one shopping trip.

</Steps>

For a place that already has an inventory, **Apply template** to it instead: items it already has
start unticked, so only the missing ones are added.

<Aside type="tip" title="Tip: Counting at the cupboard">
	On the watch, open the inventory, tap a row and press **−** or **+** while you look at the shelf.
	The row saves one change when you move on, with a moment to undo it.
</Aside>

<Aside type="tip" title="Tip: Naming your lists">
	Name a list after what it's _for_, not when you're using it: "Groceries", "Hardware store",
	"Chores", "Packing — beach". Reused lists keep the same name indefinitely. For duplicated lists,
	add the run to the name — "Packing — Lisbon, May" — so finished ones are easy to tell apart in the
	archive.
</Aside>
